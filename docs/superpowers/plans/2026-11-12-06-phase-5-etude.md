# Phase 5 — Étude : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Mode d'exécution déjà choisi : **subagent-driven allégé** (voir « Déroulement » ci-dessous).

**Goal:** January étudie au quotidien : « Commencer mon bloc » ouvre une session guidée par le Tuteur (minuteur 50/10, trois modes, « Je bloque » à 3 indices) qui coche les tâches, met à jour les acquis et crée des fiches ; l'Examinateur fait passer un quiz par module (80 % → `valide`) et les révisions espacées tournent ; la carte de compétences (graphe, radar, progression, comparaison) reflète tout cela ; le bilan du dimanche replanifie dans le budget avec l'avant et l'après ; Ctrl/Cmd K capture un lien, un texte, un fichier ou une note dans la mémoire et le journal ; plus le reliquat de la phase 4.

**Architecture:** Quatre parcours LangGraph (`quiz`, `study_session`, `replan`, `capture`) et deux agents (Examinateur `examiner`, Tuteur `tutor`) ; le Stratège gagne un mode `replan`, l'Archiviste un mode `capture`. Les agents n'importent aucune feature (contrat 6) : quatre ports de plus dans `AgentPorts` (`quiz`, `study`, `replan`, `capture`), branchés par `app/bootstrap_agents.agent_ports`. Côté back, quatre features nouvelles (`quiz`, `study`, `replan`, `capture`) et `skills` gagne son routeur ; les règles pures (révisions espacées, notes, bilan, série, radar) sont des modules sans base ni modèle ; deux tâches planifiées (`weekly_review`, `skill_snapshots`). Côté front : features `study/`, `quiz/`, `skills/` (React Flow + elkjs, Recharts), `replan/`, `capture/` (`CommandCapture` global, journal), branchées par manifeste ; le manifeste gagne des emplacements de coquille (barre du haut, surcouche).

**Tech Stack:** LangGraph, Pydantic v2 (`Prose`), SQLAlchemy 2 + Alembic, APScheduler (existant), `zoneinfo` + `tzdata` · React 19, TanStack Query, `@xyflow/react`, `elkjs`, `recharts`, Vitest, Testing Library, MSW.

**Spec:** `SPEC.md` §4.2 et 4.5 (niveaux, seuls quiz et projet font monter), §7 F9 et F13, §8 F14, F15, F18, §9.1 (Examinateur, Tuteur), §9.2, 9.4, 9.6, §11.4 (bilan dimanche 18 h), §13.3, 13.4, 13.6 (index `flashcards(due_date)`), §14.1, §14.2 (« Étude », « Compétences », `POST /capture`, `GET /journal`), §15.1, 15.3, 15.4, §17.2 à 17.4, §18.1 (phase 5), §18.3 (F9, F13, F14, F15, F18). ## Global Constraints

Toutes celles du plan directeur et du plan de la phase 4 s'appliquent : 300 lignes par fichier, 50 par fonction ; router → service → repository ; filtre `user_id` partout ; mypy --strict, ruff, import-linter (**8 contrats**, inchangés : les nouvelles features sont couvertes par les jokers) ; eslint boundaries ; textes dans `frontend/src/shared/i18n/messages/<zone>.ts` ; un dossier par composant ; extensibilité par registres et manifestes. Propres à cette phase :

- **Quiz (F9)** : un quiz par module, **8 à 12 questions** mêlant QCM, réponse courte, lecture de code et « explique avec tes mots » ; réponses ouvertes notées avec une grille, **chaque erreur a une explication** ; **≥ 80 % → acquis `valide`** ; en dessous, tâches de révision ciblées et **nouvel essai 2 jours plus tard**.
- **Révisions espacées (F9)** : fiches créées depuis les leçons et les erreurs de quiz (et de session, de capture) ; intervalles **1, 3, 7, 16 puis 35 jours** ; **une erreur ramène à 1 jour** ; file du jour **plafonnée à 15 minutes** ; un acquis `valide` dont les fiches **échouent deux fois de suite redescend à `en_cours`**.
- **Session guidée (F14)** : « Commencer mon bloc » ; minuteur **50 min de travail, 10 de pause par défaut, réglables** ; objectif, leçon **section par section avec une question de compréhension après chacune**, l'exercice, **3 questions finales** ; modes **Socratique, Feynman, Direct** ; « Je bloque » : **trois niveaux d'indices avant la solution** ; le Tuteur connaît la leçon, ses sources et la mémoire et peut dessiner au tableau ; fin : résumé, temps enregistré, tâches cochées, acquis mis à jour, fiches depuis les erreurs, une ligne de journal ; **série de jours et heures de la semaine visibles en permanence**.
- **Carte (F15)** : nœud = compétence, lien = prérequis, **couleur = niveau**, **taille = demande du marché** ; clic : preuves, offres qui l'exigent, prochaine action ; vues **graphe, radar par domaine, courbe avec un relevé par semaine** ; comparaison moi / poste cible / offre ; référence unique ; **un changement de niveau visible en moins d'une minute**.
- **Replanification (F13)** : bilan **dimanche 18 h, réglable** (heures prévues et faites, tâches terminées, quiz) ; retard redistribué **sans jamais dépasser le budget** (85 %, règles de 3.4 inchangées) ; **> 30 % de retard deux semaines de suite** → réduire le périmètre ou repousser l'échéance ; **en avance** → avancer ou approfondir ; autre déclencheur : « cette semaine je n'ai que 5 heures » ; **avant / après, validation, historique des versions**.
- **Capture (F18)** : champ global **Ctrl K / Cmd K** ; lien, texte, fichier ou note ; l'Archiviste **résume en 5 lignes**, extrait les concepts, relie aux modules, range en mémoire ; propose de **cocher une tâche couverte** et des **fiches** ; **lien illisible signalé tout de suite, texte demandé** ; **journal** chronologique (captures, sessions, quiz) avec **résumé hebdomadaire**.
- **Niveaux (4.2, 4.5)** : un agent n'écrit jamais au-delà de `en_cours` ; seuls un quiz (→ `valide`) ou un projet (phase 8) font monter ; `user_skills` fait foi, la mémoire en est le reflet (D6).
- **Sorties structurées et GLM (D97 n° 10)** : tout texte libre **à lire** d'une sortie structurée (explication, grille, retour, indice, résumé, raison, verso de fiche, ligne de résumé) est un `Prose` (ou `ShortenToMax()` dans une liste) ; restent **refusés et redemandés** : identifiants et références (`q3`, `t12`, `m2`), énoncés de question, choix de QCM, code, noms de compétences, Mermaid. Plafonds généreux sur les énoncés (refus = nouvel essai).
- **Rejeu (9.4)** : aucun effet de bord avant `interrupt()` dans un même nœud ; chaque écriture d'un port est **idempotente** (clé : session, révision, tentative, `ref_key`) ; une session chaînée part d'un contexte vierge (D97 n° 12, existant).
- **Sécurité (17.2, 17.4)** : réponses de January notées, texte de leçon, page capturée, plan courant et note de révision rendus à un agent passent par `untrusted()` ; **journaux : identifiants seulement** (utilisateur, session, quiz, tentative, module, programme, fiche), **jamais** une réponse, une question, une fiche, un texte ou une URL capturés ; **une 422 ne renvoie jamais l'entrée** ; l'URL capturée passe par `WebGateway` (garde SSRF existante).
- **Temps local** : jours, semaines (lundi → dimanche), série, échéance des fiches et bilan sont calculés dans le **fuseau de January** (`UserSettings.timezone`, défaut `Europe/Paris`) ; le back tourne en UTC.
- **Tests sans réseau ni LLM** : modèles scriptés par agent, faux ports (`tests/support/`) ; GLM 5.3 flash (Z.ai) ne sert qu'aux essais réels de 5.7 et 5.18.
- **Contrat front/back** : toute tâche back qui change l'API régénère `contracts/openapi.json` (`cd backend && uv run python -m scripts.export_openapi`) **et** `frontend/src/shared/api/schema.d.ts` (`pnpm --dir frontend gen:api`) dans le même commit ; aucune tâche front ne les touche.
- **Front (15.4)** : jamais de `window.confirm` ; état vide avec action, chargement, erreur avec « Réessayer » ; animations < 300 ms coupées par `prefers-reduced-motion` ; contraste AA (couleurs de niveau comprises, avec légende textuelle) ; navigation clavier (graphe compris) ; utilisable à 1 024 px.
